# 性能与稳定性实测

> 对应评审维度：**任务闭环与稳定性（25 分）**中的「响应速度满足使用需求」「系统运行稳定」。
> 数据来自真实压测，可一键复现：
> ```powershell
> venv\Scripts\python.exe scripts\benchmark_smoke.py
> ```

## 一、测试环境

| 项 | 值 |
|---|---|
| 运行方式 | 本地 uvicorn（`start.ps1` 同款启动方式） |
| 数据库 | SQLite（本地默认；线上为 PostgreSQL） |
| 并发 | **10** |
| 每接口请求数 | **30** |
| 总请求数 | 210（不含 LLM 采样） |
| 日期 | 2026-09-14 |

> 说明：压测对象为**确定性本地链路**（检索 / 列表 / 雷达 / 质量 / 项目 / 情报）。
> LLM 问答单独低并发采样，因为其延迟主要取决于外部模型服务，不代表本系统性能。

## 二、实测结果

| 接口 | 路径 | 成功 | 成功率 | 均值 | P50 | P95 | QPS |
|---|---|---|---|---|---|---|---|
| 健康检查 | `/health` | 30/30 | 100% | 14.3 ms | 13.8 ms | 17.8 ms | 697 |
| 赛事列表（190 条全量） | `/api/competitions` | 30/30 | 100% | 663.9 ms | 683.0 ms | 807.0 ms | 15.1 |
| 学生画像类型 | `/api/student-types` | 30/30 | 100% | 20.6 ms | 19.8 ms | 28.2 ms | 486 |
| 来源雷达状态 | `/api/radar/status` | 30/30 | 100% | 26.2 ms | 24.7 ms | 38.2 ms | 382 |
| 系统质量驾驶舱 | `/api/system/quality` | 30/30 | 100% | 47.7 ms | 31.1 ms | 97.9 ms | 210 |
| 我的项目 | `/api/users/test/projects` | 30/30 | 100% | 68.1 ms | 72.3 ms | 92.6 ms | 147 |
| 情报收件箱 | `/api/users/test/alerts` | 30/30 | 100% | 20.7 ms | 20.4 ms | 24.7 ms | 484 |

**汇总：210 / 210 成功，成功率 100.00%，无超时、无 5xx、无异常。**

## 三、结论

1. **核心交互链路在 100 ms 内**：除赛事列表外，所有接口 P95 ≤ 98 ms，用户侧感知为即时响应。
2. **并发下无失败**：10 并发持续请求，SQLite 读写未出现锁冲突或服务异常。
3. **确定性路径不依赖外部模型**：若未配置 LLM Key 或外网不可用，系统仍走本地确定性链路（同一批接口延迟不变），这是「4 秒降级」原则的性能基础。

## 四、LLM 问答延迟（外部依赖，仅供参考）

| 项 | 实测 |
|---|---|
| 成功 | 3 / 3 |
| 平均 | 23.6 s |
| 最大 | 23.9 s |

该延迟为**外部大模型服务（qwen-plus）**耗时，非本系统计算瓶颈。系统设计上：

- LLM 仅用于**自然语言表达层润色**，引用编号 `[n]`、资格门控、赛事路由、推荐排序均由**确定性逻辑**产出；
- 联网补充默认 **4 秒超时 / 单次尝试**，失败立即回退本地证据链；
- 因此 LLM 慢或不可用时，**问答仍可完成，只是文案更朴素**，不会出现空响应或长时间无响应。

## 五、已知瓶颈与改进方向

| 瓶颈 | 现状 | 改进方向 |
|---|---|---|
| 赛事列表 663 ms | 一次性返回全部 190 条完整记录 | 增加分页 / 字段裁剪；前端按分类与年份筛选后数据量显著下降 |
| 质量驾驶舱 P95 97.9 ms | 需聚合多张表统计 | 结果缓存（内容仅在数据变更时失效） |

> 上述为**真实测量后如实记录**，不做美化。两项瓶颈均不影响功能正确性，属可预期的后续优化项。
