# 校园科创导航智能体 · V0.3 创新点单页

> 参赛类别：校内 Agent 比赛　|　更新：2026-07-29　|　仓库：`campus-innovation-agent`

---

## 一句话定位

这不是又一个赛事问答机器人，而是一套**从官方变化感知，到机会决策、参赛执行，再到来源核验的可审计智能体**。

```text
官网变化 → 噪声过滤 → 字段级差异 → 人工审核
→ 用户处置 → 组合重新规划 / 转执行任务 → 作战地图风险联动
→ Agent 决策运行剧场 → 七阶段执行闭环
```

系统将“不编造、不静默覆盖、可回放、可降级”落实为数据结构、接口、交互状态和自动测试，而不是一句模型承诺。

## 七个让评委可现场验证的创新点

### 1. 决策运行剧场：让 Agent 的业务过程可审计

- 每次问答返回唯一 `run_id` 与结构化 `trace`；
- 逐节点展示状态、真实耗时、证据数、数据版本和兜底原因；
- 只公开可核验的业务动作，不暴露模型隐式思维链；
- 运行摘要持久化到 `agent_runs`，支持历史查看与冻结输入回放。

**现场看点**：评委能看到系统怎样完成“意图识别 → 赛事/年份锁定 → 证据检索 → 资格门控 → 输出/兜底”，而不只看到一段答案。

### 3. 雷达情报控制塔：把官网更新变成可处置情报

- 对官方网页、PDF、DOCX 生成规范化快照并识别字段级前后值；
- 支持包含/排除选择器、忽略正则、关注词、时区和抓取模式，过滤导航栏、时间戳等噪声；
- 展示来源健康度、连续失败状态、受影响项目与任务；
- 报名/提交截止等关键变化只进入人工审核队列，绝不自动覆盖可信事实；
- 审核后进入用户收件箱，可接受、忽略、转任务或重新规划。

**现场看点**：点击“演示截止日期变化”，能完整看到“发现差异—人工确认—影响项目—采取动作”的链路。

### 4. 科创作战地图：从单场排序升级为三路线决策

- 在资格、报名状态、周时间预算、截止冲突和已有项目约束下求解赛事组合；
- 同时输出稳妥、均衡、冲刺三条可执行路线；
- 将技能、能力缺口、赛事、材料、里程碑统一为地图节点；
- 雷达变化会把受影响的赛事和下游任务标为风险或阻塞；
- 采用组合时重新校验，任一项失效即整组回滚。

**现场看点**：评委看到的不是“Top 10 推荐”，而是有约束、有取舍、有风险联动的个人科创策略。

### 5. 七阶段执行闭环：让建议真正落到任务

- 新项目自动生成“资格核对 → 组队选题 → 报名 → 方案 → 制作 → 提交 → 答辩”模板；
- 任务支持前置依赖、阻塞原因、雷达来源和证据来源；
- 提供列表、看板、日历、跨赛事时间线四种视图；
- Agent 建议与雷达情报均可一键转为任务；
- 材料清单、进度状态和 ICS 导出共同完成执行闭环。

**现场看点**：从一句 Agent 建议出发，几秒内落到明确阶段、截止时间和可追溯依据。

### 6. 可信门控与赛事隔离 RAG：把反幻觉做到数据层

- 赛事按 `competition_id + 年份 + 文档版本` 隔离检索，避免跨赛事、跨年份串证；
- 官方来源缺失时标记 `not_found`，不补写日期、主办或奖项；
- 未核验赛事只显示为候选，已截止或硬条件不符赛事一律 `score=null`；
- 语义组件不可用时降级为确定性本地字段/原文检索；
- LLM 仅可增强自然语言表达，不能改写引用编号和门控结论。

**现场看点**：系统会明确说“不确定”或“不能推荐”，而不是为了完整答案制造确定性。

### 7. 质量驾驶舱与 4 秒降级：稳定性也可演示

- `#/quality` 将 15 项正式指标、48 项回归、86 条金标问答、运行健康度和安全门禁做成可视化驾驶舱；
- `GET /api/system/quality` 同时提供机器可读契约，冻结评测结果与当前运行指标分开返回；
- 运行态展示来源健康、待人工审核与安全门状态；
- 联网补充默认单次超时 **4 秒**、仅尝试 **1 次**，失败立即回退本地可信证据链；
- 用户 API 由短期 HMAC 签名会话绑定资源所有者；管理写操作另受 `X-Admin-Token` 保护，外部 URL 获取保留 SSRF 防护；
- 用户画像最小化采集且可删除，关联项目和任务同步删除。

**现场看点**：断网不等于系统失效，历史评测也不会被冒充成实时成绩。

## 与常见方案的本质区别

| 维度 | 普通赛事网站 / 通用 AI | 本智能体 V0.3 |
| --- | --- | --- |
| 官网发生变化 | 等人工发现，或直接覆盖旧值 | 雷达识别字段差异，人工审核后再进入事实与执行链 |
| Agent 过程 | 只给最终文本 | `run_id` + 可审计节点 + 耗时 + 证据数 + 版本 + 兜底 |
| 可信边界 | 只在文案中提醒 | 来源完整性门控、人工审核与候选信息隔离 |
| 推荐方式 | 单场排序 | 资格/时间/冲突约束下的稳妥、均衡、冲刺组合路线 |
| 推荐之后 | 收藏或跳转官网 | 七阶段项目模板 + 任务依赖 + 四种执行视图 |
| 外网失败 | 长时间等待或无法回答 | 默认 4 秒、1 次尝试后回退本地可信证据 |
| 质量数据 | 历史指标与实时状态混在一起 | 冻结评测与运行指标明确分栏 |
| 安全边界 | 依赖提示词约束 | 签名用户会话、Admin Token、SSRF、防静默覆盖、最小化采集、可追溯证据 |

## 对应工程导向评审标准

| 评审项 | 本项目的可核验落点 |
| --- | --- |
| 落地价值（30） | 解决信息失真、变化滞后、推荐不可执行三类真实痛点；数据、规则和项目模板可迁移到校内奖学金、科研项目、实习机会等场景。 |
| 任务闭环与稳定性（25） | 雷达输入到人工审核、重规划、转任务、七阶段执行和证据核验形成端到端闭环；联网 4 秒降级、来源失败保留可信版本。 |
| 工程质量（20） | FastAPI/SQLAlchemy/原生 SPA 分层；运行日志与错误处理；Docker/本地部署；48 项回归测试及质量接口。 |
| 交互与体验（15） | 决策剧场、三路线作战地图、列表/看板/日历/时间线和行动收件箱。 |
| 安全合规（10） | 签名用户会话、数据最小化、画像删除、Admin Token、SSRF 防护、人工审核门和真实来源追溯。 |
