# V1.0 · 3–5 分钟评审演示脚本

> 建议成片：**最长 5 分钟（按 3—5 分钟上限编排）**，1920×1080，浏览器缩放 90%–100%。  
> 核心叙事：**一条官网截止日期变化，如何被安全地发现、审核、转化为决策与任务，并最终回到公开官方来源。**

现有 `demo/campus-agent-demo.mp4` / `.webm` 为早期功能录屏；提交 V1.0 时建议按本脚本重新录制，以完整覆盖雷达控制塔、作战地图、决策运行剧场和执行闭环。

---

## 一、录制前准备

1. 启动服务并打开 `http://127.0.0.1:8000/`，确认 `/health` 返回正常；
2. 准备测试账号 `test / test123`，画像中填写技能和每周可用时间；
3. 准备管理员令牌，点击右上角“管理员”完成验证，确保“立即扫描”和“演示截止日期变化”按钮可见；
4. 确认至少一个监控来源，并让该来源对应赛事已加入“我的项目”，以便演示项目/任务影响；
5. 预先运行 59 项回归测试与 15 条量化指标用例；录屏时无需展示终端滚屏，直接展示「质量驾驶舱」页面；
6. 关闭个人书签栏、通知与无关标签页；提前验证一条 Agent 回答能返回 PDF 引用；
7. 如需稳定展示联网兜底，可在对应分镜前临时断开外网。本地服务和可信证据链不依赖外网。

## 三、建议保留在画面中的关键特写

### 特写 A：雷达不是“爬虫列表”

画面至少同时包含以下三处：

- 来源健康分数或连续失败状态；
- 截止日期字段级前后值；
- “确认变化”按钮或用户收件箱操作。

一句话强调：**“抓到变化不等于写入事实，关键字段必须人工审核。”**

### 特写 B：决策运行剧场不是思维链

至少停留 5 秒，让评委看清：

- `RUN` 标识；
- 节点数、证据命中、节点耗时；
- 数据版本与兜底/阻断状态。

一句话强调：**“这里只公开业务审计轨迹，不暴露模型隐式推理。”**

### 特写 C：决策运行剧场可审计

至少停留 8 秒，让评委看清：

- 每个业务节点的状态和耗时；
- 数据版本与证据数；
- 联网失败时的降级原因；
- 历史运行与冻结输入回放。

一句话强调：**“没有官方来源或关键证据不完整时，系统会明确标为候选，不能进入正式推荐。”**

### 特写 D：作战地图和项目工作台确实联动

不要只扫过三条路线，应明确指出一个风险节点，并在项目时间线或任务阻塞状态中找到它的下游影响。

一句话强调：**“官网变化不是孤立通知，它会进入个人决策和实际执行。”**

## 四、现场网络正常时的替代讲法

如果联网搜索在 4 秒内成功，不必人为等待失败。保留正常结果，并说明：

> “联网结果作为单独的‘仅供参考’区域展示，不会混入本地 `[n]` 官方引用；配置仍限制为单次 4 秒、1 次尝试，外网不可用时自动进入本地证据路径。”

如果要现场验证降级，可在页面已经加载后临时关闭 Wi-Fi，再发起一次涉及“最新动态”的问题。验证完成后恢复网络；不要在扫描雷达或打开官方链接时断网。

## 五、异常预案

| 异常 | 现场处理 |
| --- | --- |
| 雷达没有监控项 | 进入数据维护创建一个已核验赛事监控项，再回到雷达；录制前优先准备好，避免现场配置。 |
| “演示截止日期变化”按钮不可见 | 点击右上角“管理员”，输入令牌完成验证；普通用户看不到管理写操作是权限控制的正常表现。 |
| 雷达变化未影响项目 | 先把监控列表首个赛事加入“我的项目”，再重新生成演示变化。 |
| Agent 未返回 PDF 引用 | 从已验证赛事详情进入问答，或使用已确认能命中的数学建模/软件杯问题；不要临时依赖外网搜索。 |
| PDF 坐标预览不可用 | 证据页仍展示页码、原文、官方链接与定位状态；说明这是系统的显式降级，而非伪造高亮。 |
| 外网请求超时 | 等待最多约 4 秒，展示决策剧场的兜底原因和本地证据回答，这本身就是稳定性演示。 |
| 质量接口中的冻结评测时间较早 | 强调冻结结果与运行态分栏；录制前运行正式评测，确保提交材料中的时间与版本一致。 |

## 六、数据与口径检查

录屏字幕、讲解词和提交文档统一使用：

- **190 条**赛事数据；
- **154 条**已锚定官方来源；
- **7 条**达到正式推荐标准（2026-09-13 快照，随报名截止动态变化）；
- **59 项**自动回归测试（含 13 项子测试）；
- 另有 **15 条**量化指标用例；
- 联网补充默认 **4 秒 / 1 次尝试**。

不要把“154 条有官方来源”讲成“154 条可正式推荐”，也不要把冻结评测指标说成当前实时表现。
