# 参赛验收矩阵

更新：2026-10-03。依据用户提供的命题五和六项提交要求。原始比赛手册尚待提供，因此不确认历史摘录中的评分权重、赛道或答辩时长；一等奖是优化目标，不是可保证的结论。

## 提交材料

| 要求 | 实现与证据 | 验收边界 |
| --- | --- | --- |
| 可运行作品与演示身份 | Python 启动、Docker 配置、`test/test123` 一键体验 | 本地浏览器已验证；Docker daemon 与线上部署仍需目标环境验收 |
| 技术文档 | `ARCHITECTURE.md`、`DEPLOYMENT.md`、作品说明 | 架构含输入、处理、输出、兜底；字段规则以实现为准 |
| README | 环境、依赖、启动、测试、常见问题 | 默认 Python 启动，Docker 须显式选择；密钥不打包 |
| 不少于 10 条正式用例 | 15 条正式评测，正常、异常、边界和安全回归 | 实测数量与结论见 `QUANTITATIVE_EVALUATION.md`，不是模拟得分 |
| 3–5 分钟演示视频 | 现有 `demo/演示视频.mp4`，208.05 秒 | 按用户要求不改动；视频中的旧指标不代表当前验收结果 |
| 合规说明 | `COMPLIANCE.md`、`THIRD_PARTY_NOTICES.md` | 官方资料可追溯；真实注册画像不进入公开身份或队友候选列表 |

## 核心规则

| 挑战 | 应有行为 | 可复现依据 |
| --- | --- | --- |
| 官网存在但字段证据缺失 | 目录候选、无评分、不能创建新项目 | `test_security_and_readiness.py` |
| 赛事截止或资格不符 | `ineligible` 与 `score=null` | `test_trust_rules.py` 与正式评测 |
| 未知学历或团队人数 | 不补本科生或 1 人，不给错误资格结论 | 严格枚举与来源审计 |
| 同名多年份、指定不存在年份 | 追问或明确最新完整证据版本，不偷换年份 | Agent 版本消歧测试 |
| 问答引用 | 点开官方原文、页码、链接、日期和文件指纹 | 浏览器检查与 `test_official_sources.py` |
| 精确时刻与录入闭环 | 官方钟点原样保存，截止瞬间不评分，ICS 转为 UTC，原文进入检索 | `test_deadline_precision.py`、`test_admin_suggestions.py`、`test_rag_provenance.py` |
| 管理接口无令牌 | 未配置为 503，缺失或错误为 401 | 安全回归与受保护写接口 |
| 来源后来降级 | 已有项目保留并提醒，不继续正式评分 | 项目降级回归 |
| 评测真实性与复现 | 152 项回归、26 项子测试、15 条正式验收、786 条自动模板问答；不宣称模板为人工金标 | `evals/README.md`、逐条结果与代码/数据/数据库指纹 |
| 未扫描或陈旧来源 | 未扫描不计为健康，陈旧成功降级，前后端统一状态 | `test_template_evaluation.py` 与浏览器 `UNSCANNED` 验证 |

## 仍需真实材料

1. 原始比赛手册，用于核对正式评分细则和提交格式。
2. 至少一轮真实学生试用。记录匿名身份、任务、耗时、成功与失败点，不填虚构满意度；模板见 `VALIDATION_RECORD.md`。
3. 在目标部署环境轮换曾泄露的数据库凭据，设置独立管理员令牌并复核匿名请求。仓库修改不能替代 Render 控制台操作。
4. 2026-10-03 快照有 6 条证据完整且可报名赛事。推广前继续补真实官方资料，不能为了演示把历史日期后移或放松门控。
5. 已支持有原文证据的精确截止时刻与时区披露，但旧数据仍有日期级通知，不能宣称全库均已完成小时级补证；缺失时间、学历、人数和材料保持未知。

提交时附实际评测结果、源码包 SHA-256 和现有视频，不把历史压测、金标结果或合成夹具成绩当成真实用户效果。
