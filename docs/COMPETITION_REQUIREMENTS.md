## 一、我们所属：赛道与命题

### 赛道判定：**中兴赛道**（确定）

手册设「中兴赛道」「揭榜挂帅赛道」两个赛道，**每支队伍仅可选择一个赛道、一个命题参赛**。

- 中兴赛道：面向**校园管理、学习服务、资料管理、办事导航**等真实需求，鼓励开发可演示、可复用、可在学院或学校范围内试点推广的智能体应用。
- 揭榜挂帅赛道：围绕**企业真实业务**（中兴通讯 / 华泰证券的金融行情、上市公司事件、智能问数）。

本作品服务在校生科创参赛场景，属校园学习服务与办事导航 → **中兴赛道**，无歧义。

### 命题判定：**命题五「自主命题智能体」**（✅ 已与队长确认）

中兴赛道共五个命题，与本作品相关的是命题三与命题五：

| 命题 | 目标用户 / 场景 | 与本项目吻合度 |
|---|---|---|
| 命题一 理论学习 AR 视频创作 | 政治理论学习视频创作 | 无关 |
| 命题二 专业课助教 | 课程学习、题目解析 | 无关 |
| **命题三 校园综合服务** | 在校生和新生；校园办事、校园生活、**活动查询**、资源指引 | **部分吻合**：竞赛信息可归入「活动信息聚合」，但本作品主业是赛事**决策与执行闭环**，不覆盖办事流程导航、校园 FAQ、建筑指引等 |
| 命题四 学习 DDL 与资料管理 | 课程资料、DDL 提醒 | 部分沾边（有提醒能力），但主场景不同 |
| **命题五 自主命题** | 结合在校生学习、生活、**发展**与校园服务中的实际需求，**自主发现问题**并开发有明确应用价值的智能体 | **高度吻合**（见下） |

**命题五对照证据**：

| 命题五要求 | 本作品实现 |
|---|---|
| 自主发现问题、明确目标用户与核心痛点 | 定位「学生准备科创竞赛时信息真假难辨、决策不可解释、变化无法落地」 |
| 典型任务：需求调研、场景定义、**信息采集与整合** | 官方来源雷达：网页/PDF/DOCX 抓取、噪声过滤、字段级差异、人工审核 |
| **智能问答** | Agent 问答，答案内联 `[n]` 角标 + 可点击官方依据 |
| **个性化推荐** | 画像驱动推荐 + 资格门控 + 组合优化（稳妥/均衡/冲刺三路线） |
| **任务提醒或流程辅助** | 七阶段项目工作台（资格核对→组队选题→报名→方案→制作→提交→答辩）+ 情报收件箱 |
| 具备清晰的**输入—处理—输出和兜底机制** | 决策运行剧场 + 联网 4 秒降级 + 来源异常保留最后可信版本 |
| 数据集由参赛者自行准备 | 190 条赛事样本，154 条锚定官方来源 |

### 命题五的三条硬性要求（原文）

1. **自行明确目标用户、核心痛点和数据来源**；
2. **具备清晰的输入、处理、输出和兜底机制**；
3. **数据集由参赛者自行准备**。

### 命题五「评审关注」六项 × 本作品对照

| 评审关注 | 本作品对应 | 现状 |
|---|---|---|
| **选题价值** | 解决「学生备赛找不到可信信息、决策不可解释、变化无法落地」 | 🟡 痛点有写，但缺少"为什么值得做"的量化论证 |
| **需求真实性** | 《作品说明》新增「需求依据：用可复现的真实数据说话」 | ✅ 已补（2026-09-14） |
| **数据准备质量** | 190 条赛事样本 / 154 条锚定官方来源 / 字段级证据 | ✅ 强项，且可复现验证 |
| **功能闭环完整性** | 情报→决策→执行→答辩全链路 + 兜底 | ✅ 强项 |
| **系统可用性** | 一键启动、无 key 可跑、4 秒降级 | ✅ 强项 |
| **推广潜力** | 《作品说明》第十一节「推广与试点路径」 | ✅ 已补（2026-09-14） |

### 🔴 需求真实性怎么补：**用系统自己的真实数据反证**（不编造问卷）

命题五要求"需求调研"，但我们不必编造问卷——系统跑出来的数据本身就是最硬的需求证据，且评委复现即可验证：

| 需求假设 | 可引用的真实数据（系统可复现） |
|---|---|
| 信息真假难辨 | 190 条赛事中 **36 条（约 19%）找不到可核验官方来源**，系统标 `not_found` 而非猜测 |
| 决策门槛高 | 154 条有官方来源者中，仅 **7 条**同时具备四类关键字段证据且仍在报名期 |
| 官方信息确实会变 | 雷达监控 **12 个官方来源**，字段级差异检测记录前后值 |
| 信息分散、执行碎片化 | 单场赛事涉及报名/组队/方案/制作/提交/答辩 6 类节点，系统为此铺七阶段模板 |

> 这比编一份问卷更有说服力：评委跑一遍就能核。需求来源表述为「团队作为在校生的亲历 + 对公开赛事信息的系统核查」，不虚构受访人数。

## 二、赛程与当前时点（🔴 时间紧张）

| 阶段 | 主要安排 | 提交或产出 |
|---|---|---|
| 7 月 | 启动、报名与选题；宣讲会 | 报名表、队伍信息、赛道、命题、项目初步设想 |
| 7 月 | 技术指南发布与培训（智能体架构、RAG、部署与成本） | Demo / README / 方案书 / 评测用例 / 合规承诺书模板 |
| 8 月 | 中期检查 | 项目方案书、目标用户说明、核心流程、数据来源、工具清单、最小 Demo |
| **9–10 月** | **开发迭代与初赛评测**（线上评测：评委线上试用、**统一挑战用例测试**、**复现抽检**、技术文档审查、合规检查） | **中兴赛道提交：可运行 Demo、技术文档、README、用例集、演示视频、合规说明** |
| **10 月** | **决赛展示与答辩**（线下） | 每队 **6 分钟作品演示 + 6 分钟答辩**，并**抽取 1–2 条现场挑战用例**验证 |

**三个必须注意的点**：

1. **初赛有「复现抽检」和「统一挑战用例测试」** —— 评委不会只看你的演示，他们会自己 clone 跑、并拿统一用例考你。仓库必须开箱即跑（这一点我们已做干净环境验证）。
2. **决赛 6 分钟演示 + 6 分钟答辩** —— 是固定的 6 分钟，不是弹性区间。
3. **现场挑战用例 1–2 条** —— 系统要能扛住评委现场提出的陌生问题（降级与兜底能力会被真实检验）。

## 四、评审标准（总分 100，工程导向）

| 维度 | 分值 | 评审看什么 | 我们的抓手 |
|---|---|---|---|
| **落地价值** | **30** | 痛点明确、需求分析充分；目标用户清晰；实际应用价值；推广/复用/试点潜力 | 最高权重。要讲清「学生备赛的真实痛点」+ 试点推广路径（学院科创中心、辅导员） |
| **任务闭环与稳定性** | **25** | 完成「**输入—处理—输出—兜底**」端到端；运行稳定；处理异常与边界；响应速度 | 我们最匹配的一项：决策运行剧场 + 4 秒降级 + 来源异常保留可信版本 + 人工审核 |
| **工程质量** | 20 | 架构清晰、模块合理；代码与文档规范；**README 完整**；部署步骤明确；**日志记录和错误处理** | 架构文档齐备；README 完整；有日志与错误处理 |
| **交互与体验** | 15 | 操作顺畅、结果直观；反馈及时；**输出可解释**；学习使用成本低 | 答案内联 `[n]` 引用、运行剧场逐节点展示、三路线作战地图 |
| **安全合规** | 10 | 不使用未授权敏感数据；脱敏到位；权限控制合理；**仅收集必要数据**；**引用来源真实可追溯** | 官方来源锚定、SSRF 防护、最小采集、HMAC 会话、画像级联删除 |

> 💡 权重信号：**落地价值 30 + 任务闭环 25 = 55 分**，占一半以上。答辩叙事应压在「真实痛点 → 端到端闭环 → 兜底可信」，而不是堆技术名词。

## 五、参赛注意事项（合规红线）

1. 作品须由队伍独立完成，不得抄袭、剽窃或冒用他人成果。
2. **允许使用开源框架、公开模型和第三方工具，但须在文档中说明来源、用途和使用方式**。
   → 我们用了 FastAPI / SQLAlchemy / qwen-plus / duckduckgo / （可选）Chroma、sentence-transformers，文档中需逐项列明。
3. **不得使用未授权的真实敏感个人信息**；涉及学生信息、课程资料、金融数据或校内事务数据时，应遵守数据合规与隐私保护要求。
4. **作品应保证可运行、可演示、可复现**；组委会有权进行**复现抽检**和合规审查。
5. 发现严重抄袭、数据违规、虚假演示，可取消资格。
