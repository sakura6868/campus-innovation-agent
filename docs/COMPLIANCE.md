# 数据来源、隐私与合规说明

_V1.0 竞赛提交版合规说明，更新于 2026-09-14。_

---

## 📚 数据来源

核心赛事数据来自赛事组委会、政府教育部门或高校官网公开发布的 PDF/Word 通知。五份核心文件的 URL、获取日期、来源检查日期和 SHA-256 记录在 `data/core_competitions_manifest.json`。

每个核心字段保存 PDF 页码或网页原文、文档名、官方链接、获取日期、最后来源检查日期和可信等级。系统不把搜索摘要、自媒体文章或模型生成内容标记为 A 级事实。`verified/A` 表示官网来源与关键证据通过完整性规则，不表示系统替代用户或主办方完成最终资格确认。

联网搜索结果始终位于独立「仅供参考」区域，不会混入本地 `[n]` 官方引用或直接更新赛事事实。

## 🔐 个人信息处理

系统只处理用户主动填写的学历、年级、专业、技能、竞赛经历、每周可用时间和预期队伍人数，用于资格门控、匹配评分和项目规划。

系统不要求身份证号、详细住址、私人联系方式、学号、未公开成绩或生物识别信息。演示账号使用虚构画像，不包含真实个人身份信息。

## 🗑️ 删除与最小化

用户可在“我的画像”中删除画像。删除操作同时移除该用户的项目、任务和材料状态；公开赛事、官方证据和其他用户数据不受影响。

项目表不复制官方截止日期，只保存赛事 ID。这样可以避免用户项目中的日期副本与官方 Ground Truth 发生漂移。

## 🔑 会话与权限控制

- 用户名密码验证通过后，后端颁发有过期时间的 HMAC 签名会话；令牌只保存在当前浏览器 `sessionStorage`。
- `/api/users/{user_id}/...` 、带 `user_id` 的 Agent 问答和运行回放会校验会话主体；未登录返回 `401`，跨用户访问返回 `403`。
- 云端部署使用独立 `AUTH_TOKEN_SECRET`；管理员写操作使用另一个 `ADMIN_API_TOKEN`，两者不共用。
- 公开赛事与官方证据保持只读公开，便于评委核验来源；个人画像、项目、情报收件箱与历史运行不公开。

## 🛡️ 自动决策边界

- 官网来源或关键证据不完整的赛事仅显示为候选信息，不进行资格判断或匹配评分
- 已截止赛事不评分
- Agent 回答带官方引用，不以模型常识替代缺失规则
- 全国统一日期不存在时明确回答“未给出”，不使用校内日期冒充全国日期
- 同名多年份有官方来源锚点时可显式声明使用最新届；若整体关键证据未齐，同时标注候选且不评分；无法锁定官方来源时追问

官方来源雷达不直接改写主表。关键日期或资格变化只生成待审核事件，审核前继续使用最后可信版本。外部 URL 抓取校验公网 HTTP(S) 目标，拦截本机、内网、链路本地与非授权协议，降低 SSRF 风险。

推荐结果用于信息辅助，不替代赛事组委会、学校教务部门或用户所在院系的最终资格审核。

## 📦 存储与传输

默认部署使用本机 SQLite。若启用外部 LLM、联网搜索或远程 Chroma，部署方应另行评估数据出境、服务条款、日志留存和访问控制。LLM 只获取问题、必要画像摘要和已选证据；不应向外部服务传输密码、管理员令牌或完整用户数据库。
