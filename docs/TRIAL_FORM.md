## 〇、给你的说明（开发者视角，发给同学前删掉本节）

**什么算真人验证、什么不算（关键）：**

| 表的哪一部分 | 谁写 | 是否算真人验证 |
| --- | --- | --- |
| 「① 你实际做了什么」「③ 你的主观评价」 | **真人本人** | ✅ 算，评委认 |
| 「② 系统给你的结果」截图/粘贴 | 真人截图或粘贴 | ✅ 算（客观事实） |
| 「④ 系统侧证据」(intent/引用数/延迟) | 开发者用 `scripts/trial_replay.py` 复跑生成 | ⚠️ **不算用户反馈**，只是系统客观行为的佐证，需与 ①③ 并列 |

**结论**：让我"用系统跑一下再给反馈"≠真人反馈。反馈主体必须是人。我能做的是：
1. 把同学填的提问，用 `trial_replay.py` 复跑一遍，把系统**真实输出**贴进「④ 系统侧证据」；
2. 把你汇总好的表整理进 `VALIDATION_RECORD.md` 第四节——但**不替任何人编评价**。

**发给同学前**：删掉本节，保留第一、二、三节即可。

## 四、开发者：如何生成「④ 系统侧证据」

1. 把每位同学「①」里的问题整理成 `scripts/trial_inputs.json`：
   ```json
   [
     {"trial_id": "A", "question": "蓝桥杯报名什么时候截止"},
     {"trial_id": "B", "question": "推荐适合计算机大二的比赛"},
     {"trial_id": "C", "question": "互联网+ 怎么组队"}
   ]
   ```
2. 确保本地服务在 `http://127.0.0.1:8011` 运行，然后：
   ```bash
   venv/Scripts/python.exe scripts/trial_replay.py
   ```
3. 输出 `scripts/trial_replay_result.json`（系统真实返回）+ 终端打印每题的 intent/引用数/延迟，直接抄进「④」。

> ⚠️ 复跑只产生**系统行为证据**，不产生用户评价。用户评价必须来自「③」。
